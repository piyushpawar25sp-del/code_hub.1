Relational Structure

tables, tuples, and the rules that keep a relation well-behaved

§1 What a relation is

Definition The relational model (RM) represents a database as a collection of relations — and a relation is nothing more than a table of values.

Every row in the table is a collection of related data values representing one real-world entity or relationship. The table as a whole is a collection of such relationships — which is exactly why it's called a relation.

A tuple (row) holds all the data for a single instance of the table — say, a person named Deepak. Every tuple must carry a unique identification, or key, based on its data.

§2 Fields, records, and domains

Fields and records are the two basic components of any database:

TermAlso calledMeaning
FieldAttribute / columnA vertical category of data
RecordRowA horizontal grouping of unique field data
Domain The set of permitted values for an attribute.

Take an account relation with attributes acc_no, br_name, balance. The domain of br_name is the set of all valid branch names — e.g. Balives, Treasury, Market Yard, Rail Lines, Vijapur Road.

  • Domain values must be atomic
  • Two different attributes may share the same domain
  • A domain may include null — not zero, not an empty string, just "value unavailable"

§3 Entities, as rows

A relational-database entity represents a real object that's uniquely identifiable and carries the attributes relevant to the application — including its relationships to other entities. In the database, an entity is represented by an individual row in a table.

§4 Properties every relation must satisfy

  1. Atomic values — every value in the table is indivisible
  2. Same domain per column — all values in a column come from the same domain
  3. Column order doesn't matter
  4. Row order doesn't matter
  5. Unique column names — since columns are referred to by name

§5 RDBMS — putting the model into software

Definition RDBMS (Relational Database Management System) is a DBMS built on the relational model introduced by E. F. Codd. Data lives in database objects called tables.

RDBMS is the foundation for SQL and for essentially every modern database system.
