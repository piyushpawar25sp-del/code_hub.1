§4 Functional dependencies (FDs)

/* Lines 141-143 omitted */

Example — in an Employee table, if changing an employee's name always means their ID changes too, then Name depends on ID:

ID → Name

4.1 · Full functional dependency

A → B is full if removing any attribute from A makes the dependency stop holding.

{Emp_no, Project_no} → Hours

Neither Emp_no alone nor Project_no alone determines Hours — you need both. Hours worked on a project can't be pinned down by the project number alone; it needs the employee number too.

4.2 · Partial functional dependency

An FD A → B is partial if some attribute can be removed from A and the dependency still holds — i.e. a non-key column depends on only part of a composite key.

{Emp_no, Project_no} → Ename   i.e.   Emp_no → Ename
