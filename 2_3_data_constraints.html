Data Constraints

the rules that stop bad data from ever getting in

§1 What a constraint is

Definition A data constraint (integrity constraint) is a mechanism that restricts a user from entering invalid data into a table — it enforces rules or conditions on an attribute. If an insert or update doesn't fit the rule, it's rejected outright.

§3 Domain Integrity Constraint

Used to keep values consistent with a user's specification. It comes in two flavors:

ConstraintWhat it does
Not NullBy default every column accepts nulls; this constraint blocks null values from being entered in that column.
CheckDefines a condition every row must satisfy. A single column may carry multiple check constraints.
Example: a Salary column with the check value must be greater than 5000.

§5 Referential Integrity Constraint

Used to create a parent–child relationship between two tables, enforced through a foreign key — a column (or group of columns) whose values are drawn from the primary or unique key of another table.

TermAlso called
Table holding the primary keyParent table / Master table / Referenced table
Table holding the foreign keyChild table / Detail table / Referencing table

Ground rules

  • The foreign key column may have a different name than the primary/unique key it references, but must match its datatype and size exactly
  • A foreign key can even reference a column in the same table
  • The referenced parent column must itself be a primary key or unique key
  • A parent record can be deleted only if no child record references it
  • A parent record cannot be updated while a child record still references it
  • ON DELETE CASCADE allows child records to be deleted automatically when their parent record is deleted
