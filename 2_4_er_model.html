E-R Model, in depth

attribute types, cardinality, participation, and strong vs. weak entities

§1 Quick recap

The Entity-Relationship model is a semantic model built from three parts: entity sets, relationship sets, and attributes. An entity is a distinguishable real-world object (a person, a book); an entity set groups similar entities (all students, all teachers); a relationship is an association among entities.

§2 Types of attributes

Simple attribute

An attribute that cannot be divided into smaller meaningful parts. Example: Roll_no, Salary, City.

Composite attribute

An attribute made of multiple components that each contribute to the value. Example: Name = First_name + Last_name.

Single-valued attribute

Each entity holds exactly one value for the attribute. Example: Age or Student_id.

Multivalued attribute

One entity can have multiple values for the same attribute. Example: Phone_no or Skills.

Customer: Name is composite, Phone_no is multivalued, Date_of_birth is stored, Age is derived, Cust_id is the key

§3 Constraints on an E-R schema

An E-R schema may need to satisfy constraints that its contents must obey. There are two kinds:

3.1 · Mapping cardinality

Defines how many entities of one set relate to how many entities of another — used specifically for binary relationships.

CardinalityMeaning
One-to-oneOne entity in A associates with exactly one entity in B
One-to-manyOne entity in A associates with zero or more entities in B
Many-to-oneSeveral entities in A associate with exactly one entity in B
Many-to-manySeveral entities in A associate with several entities in B

one-to-many: one loan is connected to only one customer via borrower, but one customer can have several loans

3.2 · Participation constraints

TypeMeaningExample
Total participationEvery entity in the set participates in at least one relationship of REvery loan must appear in the borrower relationship
Partial participationOnly some entities in the set participate in RNot every customer has taken a loan

double line = total participation (every loan has a borrower); single line = partial (not every customer has borrowed)
